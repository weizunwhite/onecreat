# OneCreat × 科创工作流 —— 架构纲要 v1(2026-08-23,编排者综合稿;v1.1 修正 N1/N4,见 00_架构规划 §10.1)

> 本纲要由三份调研报告(01 NASApp 科创工作流现状 / 02 OneCreat 现状与架构约束 / 03 pi-dsh 双引擎可行性)综合而成,是「规划文档」与「drawio 架构图集」的共同输入。图与文必须与本纲要一致;本纲要与调研报告冲突时,以调研报告的**事实**为准、以本纲要的**决策**为准。

## 0. 一句话定位

**OneCreat = 零一优创的"科创项目操作系统"**:一个 Go 单二进制本地服务器(`onecreat-web`)+ 浏览器 Web UI,内置「科创工作流」这套方法论(注册表 + 40+ skill + 证据台账),底层由可切换的 agent 引擎(dsh / pi / native)驱动,身份与计量接教师平台账号系统。**先内部用(创始人/自家老师),架构上预留外部商业化(按机构/老师/学生分权、按档位与产出物计费)。**

形态拍板:**不做桌面 App 壳**,就是 `onecreat-web`(已有 Web 模式,主分发形态)——本地起服务、浏览器当 UI,与 dsh 的 `dsh web` 同形态。

## 1. 八条设计铁律(全部继承自现有架构守卫,不新造)

1. **科创工作流是应用策略,只长在 `control.Controller` 之上**;绝不碰 `engine.TurnEngine` 接缝(`boundary_test.go`),绝不让 `internal/engine*`/`internal/agent` import 新领域包。
2. **阶段/课题/项目 状态不上 Controller、不上 turnState**;新建领域服务自持锁;`controller.go ≤ 950 行`、`app.go ≤ 900 行 / 方法 ≤ 26 行` 红线不动。
3. **门禁走 `toolpolicy.Pipeline`**(plan mode → gate → PreToolUse → checkpoint → 注入);任何引擎(native hosted / dsh、pi gated)都经同一条 `Pipeline.Before`,`requireToolGating` 无配置开关可绕。⚠ 已知口径限定:dsh `handlePreExecute` 在 `ask` 且无审批者(headless)时放行——材料作业大量 headless,M2 须拍板是降级放行还是转进决策收件箱。
4. **注册表唯一真源**:阶段/材料/skill/依赖/输出/平台 file_type 全在一份 `workflow_registry.json`(内嵌进二进制,启动即校验,未注册类型 fail-closed);组别/来源/十流程等枚举**只定义一次**,并加机械守卫(round-trip / 枚举覆盖测试),杜绝 NASApp 的三份漂移。
5. **文件位置即状态,项目目录即真源**:项目实体原地接管 `/Users/localwork/课题/01_在研项目/P26X-NNN_短名/`(七目录 + `project.json`),OneCreat 不搬数据、不建第二真源;项目级运行状态用 **append-only `.onecreat/workflow.jsonl`**(与 `tests/hardware_evidence.jsonl` 同构)。
6. **业务决策点 ≠ 安全审批**:立项建档/未立项/准则 confirm/段位拨动 是"老板亲手点"的产品决策,新建 **决策收件箱(Decision Inbox)**,与 `approvalBroker` 并列、语义独立、**YOLO/bypass 不能跳过**。
7. **引擎按"新会话"选择,写进 `session.Record.Engine`(write-once),会话中途换引擎硬拒**;全局配置只做默认值。dsh 为默认,pi 可选,native 保留作开发/兜底。
8. **SaaS 红线不变**:真实模型名不得出现在 UI/日志/事件流/错误体;方法论正文(skill/注册表/KB)随发行包内置,**只有身份与计量走网**,断网能干活。

## 3. 领域模型(核心实体)

| 实体 | 身份/存储 | 状态 | 备注 |
|---|---|---|---|
| Project 项目 | `P26[CBG]-NNN`;`<项目根>/project.json`(保留 NASApp 格式 + 新增 `stage`/`stage_updated_at`);七目录 | stage 1–8(孵化/立项/生产/发布同步/项目协作/授课交付/结题冲刺/回流归档) | 目录永不搬家不改名;`session.Record.ProjectID` 反向关联;项目服务挂 workspace scope |
| Topic 题卡 | 扫描 `00_产题评题/{产题,评题}` + `_未立项` + `P26*` 合并而成(索引只是产物) | candidate → establishing → established / unestablished | 归一化 key 一份实现,必须与历史 key 逐字节一致 |
| Material 材料(25 种,v17 核实,早先调研误计 24) | 注册表条目:type/stage/kind/skill/deps/outputs/platform.file_type | 五段:source/establish(conversational)· collab/platform/sprint(oneclick) | 未注册 fail-closed;别名表兼容旧名 |
| MaterialJob 材料作业 | = 一个 Controller 会话(kind=material, ProjectID, Engine 任选) | queued→running→succeeded/failed | 依赖注入(读上游产物全文)、重试 1 次、假成功检测、看图质检、组装说明 |
| Thread 对话线程 | `.onecreat/threads/<id>.json`(项目内或选题工坊内) | queued→running→awaiting_input→succeeded→**awaiting_decision**→decided | conversational 材料专用;决断由决策收件箱完成 |
| Decision 决策项 | 决策收件箱(进程内服务 + 持久化到 workflow.jsonl) | pending→accepted/rejected(含 reason) | 类型:建档/未立项/准则confirm/段位/其他;**不受 YOLO 影响** |
| EvidenceLedger 证据台账 | `<项目>/02_平台材料/<短名>_evidence_ledger.json`(沿用 skill 契约)+ 运行时 Receipt | items{slot,perishable,consumers,status} | 三站接力(论文骨架→教案→研究日志→结题装配)+ OneCreat evidence 引擎对账 = 闭环 |
| TopicRules 产题准则 | `00_产题评题/准则/`(md 正本,版本化)+ 反馈库 json | draft→confirmed→(rollback) | Compose 时运行态注入,**不进系统前缀缓存** |
| Numbering 编号登记簿 | 接口 `Issuer`;本地 `课题/.onecreat/project_codes.json` 或 NAS API 或平台 | — | 迁移期保留 NAS 权威(HTTP 适配),冻结日一次性切本地 |

不迁/不做:C/B 卡教务档案、选题包 pack_state(可弃)、iOS/Android/desktop-more UI、macfs 远程受控链、project_sync rsync 编排(保留为可选外部脚本/工具)、pi-daemon/预算/推送/晨报。

## 4. 关键运行时序(两条主链)

**A. 一键材料(oneclick)**:UI 点「生成 教案」→ workflow 服务查注册表 → 拓扑排序 + 依赖检查(缺技术方案 → 先排技术方案或阻塞提示)→ 为该材料新建会话(ProjectID, Engine=用户所选/默认 dsh)→ 组 prompt(skill 调用 + 依赖产物全文 + 准则注入 + 项目记忆)→ Controller.Submit → 引擎跑(工具调用经 Pipeline 门禁)→ 产物写入项目七目录对应桶 → 假成功检测/重试/看图质检 → 证据 Receipt + ledger 对账 → append workflow.jsonl → SSE 事件 `workflow.material_done` → UI 工作台刷新。

**B. 对话型(立项)**:课题库点「立项」→ 查活跃线程(同题 409)→ 新建 Thread + 会话(深度模式无 note 先 awaiting_input)→ skill idea-to-build 跑 → 产出立项依据 → 线程 succeeded → **进入决策收件箱 awaiting_decision** → 老板点「建档」→ numbering.Issuer 预告号 + 回验 → 建七目录 + project.json + 复制产题/评题/立项依据到 01_立项定题 → stage=2 → 或点「未立项」(必填 reason)→ 搬到 `_未立项/<题名>_<组别>_<日期>/` + 未立项原因.md。

## 5. 双引擎与门禁

- 引擎选择 UI:新建会话/标签时选「dsh(默认)/pi/native」;历史会话按 `Record.Engine` 装配;状态栏显示引擎名与能力表;compact/会话 rewind/branch 在 dsh、pi 下按能力禁用并给人话原因。
- pi 适配器 `internal/engine/pi`:进程拉起(复用 runtime 查找)· JSONL 帧 · `prompt→agent_settled` 一轮收敛 · 事件映射 · `pi/extensions/onecreat-gate.ts`(`tool_call` 钩子 + `ctx.ui.input("__onecreat_gate__")` 阻塞等 Go 裁定;`undefined`=deny)· `complete_step` 工具桥 · provider `onecreat-gateway`/模型 `tier-N` + `resolve` 回调取 token(解决 50 分钟轮换)· `--no-extensions --no-skills --no-context-files -na` 隔离(不信任项目本地 .pi)· e2e 五条门禁用例(deny/ask批/ask拒/计划模式拦写/取消 fail-closed)。
- 守卫补齐:`boundary_test` 加 pi 同名测试;`selectEngine` 加 `pi`;config `PiConfig` + render 回环;`Record.Engine` write-once;桌面 5 个 `boot.Build` 传 Engine;顺手接上 dsh 漏掉的 `BindSession`(CapResume 真接线)。
- 分发:`runtime/node` 共享一份;`runtime/dsh` + `runtime/pi` 两个目录;默认包只带 dsh,pi 首次切换时按需下载(沿用 arduino-cli 一键安装先例);`SKIP_SIDECARS=dsh,pi`。
- 决策建议(给老板):先做 P0+P1(5–7 人日)拿到能过门禁 e2e 的 pi spike,与 dsh 做一次真实对照,再决定是否长期双养。

## 6. 商业化预留(现在只设计不实现的接口)

- feature key `workflow`(平台 `catalog.ts` + 客户端 `useCan("workflow")`)门控整个科创工作台;档位差异(如旗舰档才开自动编排)读 `SelectedTier`。
- `AccountSession` 预留 `UserID/OrgID/Role/Students[]`;平台侧预留 `onecreat_projects(id, org_id, owner_teacher_id, student_alias, stage, updated_at)` 影子表 —— 客户端在阶段推进时上报一次(离线可缓存重放)。
- 计费事件接口 `billing.ReportOutcome(projectID, materialType, points)`:产出物维度结算,现在内部模式为 no-op。
- `numbering.Issuer` 第三实现 = 平台发号(多机构时必需)。
- `/api/onecreat/refresh` 续期缺口列为平台侧前置。
