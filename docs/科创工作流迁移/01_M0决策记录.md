## 1. 五问逐条

### 1.1 问题 1 · 发号权威 = A(迁移期 NAS 权威 → M5 一次性切本地)

| 项 | 内容 |
|---|---|
| **选项** | **A** 迁移期保留 NAS 权威(`internal/numbering` 出一个 HTTP 适配)→ 冻结日一次性切本地文件 · **B** 一步到位切本地 `课题/.onecreat/project_codes.json` |
| **拍板** | **A** |
| **理由**(规划 §9 问题 1) | 发号是"唯一权威"型数据,**双写必冲突**;A 让 M1–M4 期间 NASApp 与 OneCreat 并行使用而不打架,把切换风险压缩到 M5 的一天。B 的风险是并行期两边各发一个号,**后果不可逆**——项目编号是三端身份证。A 的额外成本很小:`Issuer` 接口本来就要写,NAS 实现只是多一个 HTTP 客户端 + 现成的 `expected_code` 回验(报告 01 §2.1① 引 `tools.ts:1290, 1330-1332`)。 |

**对后续各期的约束**

| 期 | 约束 |
|---|---|
| **M1** | `internal/numbering` 必须先落 `Issuer` 接口:`Preview(ctx, line) (code, error)` / `Issue(ctx, line, expected string) (code, error)`。同期可写 `Local`(文件实现),但**只用于单测与离线自检**,不许接真实立项链。 |
| **M3** | **必须先有 `numbering/nas.go`(HTTP 适配),M3 的立项链只许用它。** 走 NAS `/api/project-code/preview`(`web/main.py:4678`)预告 + 建档时带 `expected_code` 回验,号变了就拒绝。M3 的 CLI 验收**只对沙箱题跑通链路,不对真实候选题发号**(真实立项在 M4 上线日才切入口,见 §2.2 E04/E24/E29/E48)。 |
| **M4** | 工作台"立项"按钮直连 `Issuer`,UI 上必须回显预告号并在建档时原样带回(照抄 NASApp 确认卡的"预告号必须原样带进确认卡"规矩,报告 01 §4.3 `project_code_preview`)。 |
| **M5** | **冻结日流程(必须写成一张可勾选的 runbook,不许临场发挥)**:① 冻结 NASApp 发号(停用 §2.2 的 E29/E30/E41/E48,改只读或直接 403);② 从 NAS 拉 `project_codes.json` 全量;③ 写入 `课题/.onecreat/project_codes.json`;④ 前后条数与最大序号对账;⑤ `internal/numbering` 配置切 `Local`;⑥ 用一个**废弃线**(建议 G 线)试发一个号再回滚,确认序号池连续;⑦ 归档 NAS 那份为只读快照。 |
| **全期** | 不做双写。`Local` 与 `NAS` 两个实现**不得同时启用**;配置里只能选一个,选错要在装配期报错而不是静默回退(照 `engine` 配置键的现有口径)。 |

### 1.2 问题 2 · NAS 总库 / 学生软链 / SMB = A(外部脚本 + 一个按钮)

| 项 | 内容 |
|---|---|
| **选项** | **A** 继续由外部 `project_sync.py` 维护,OneCreat 只提供"运行同步"按钮(调外部脚本)· **B** 完全退役,只留 Mac 单点 |
| **拍板** | **A** |
| **理由**(规划 §9 问题 2) | 学生视角(NAS `2026上课/<真名>/项目文件/` 软链)、老师用 SMB 看文件、上课照片落点**三件事都依赖 NAS 总库**,退役会直接影响正在上的课。而 `project_sync.py` 是**已经跑通、与 OneCreat 正交**的外部脚本,保留成"外部工具 + 一个按钮"是成本最低的解耦。 |

**对后续各期的约束**

| 期 | 约束 |
|---|---|
| **M1** | `internal/project` 的 `bucket.Classify(materialType, relpath)` **必须吸收 `project_sync.py` 的"分类投放"业务规则**(哪个文件进哪个桶),规则正本以 `课题/01_在研项目/README.md` §三判例表 + §五机制目录白名单为准。**OneCreat 绝不重写 rsync/scp/软链编排**——规划 §4.11 的不迁清单在这一条上不放宽。 |
| **M4** | 工作台加"运行同步"按钮。执行契约照抄 `macfs_agent.py` 的两条设计(报告 01 §5.3):**① 动作白名单 + argv 数组 + `shell=False`;② 独立审计日志**。白名单只允许:`project_sync.py --all`、`project_sync.py <短名>`、`refresh_board.py`。**不许把用户输入拼进命令行**,短名必须先过 `P26[CBG]?-\d{3}_` 前缀/字符集校验。 |
| **架构边界** | 这个按钮是一个**新的受控外部执行点**,不是普通 bash 工具调用:它由 UI 直接触发、不经模型。因此它**不走 `toolpolicy.Pipeline`**(那条链的语义是"要不要允许模型跑这个工具"),而是走独立的允许表 + 审计。若日后要让模型自己触发同步,才需要把它注册成内置工具并接 Pipeline。 |
| **M5** | 同步链路**不停用**。M5 只停"发号 / 立项 / 材料生成 / 题板"那几类入口(§2.2),`project_sync.py` 与 NAS 总库长期保留。 |
| **长期** | NAS 总库继续是"学生视角 + SMB 视角"的镜像;**Mac `课题/` 仍是唯一真源**(`project_sync.py:19` 的硬约束不变)。 |

### 1.3 问题 3 · 教师平台项目包上传 = A(M0–M5 只走 iOS)

| 项 | 内容 |
|---|---|
| **选项** | **A** 继续只走 iOS(写 token 只在 Keychain,NAS 后端绝不持有)· **B** 让 OneCreat 持老师 token 直传 |
| **拍板** | **A**(M0–M5 全期) |
| **理由**(规划 §9 问题 3) | "写凭证只在 iOS Keychain"是 NASApp 已经立下的安全边界(`NASApp/CLAUDE.md` 第六节;唯一例外是 2026-08-20 拍板的服务端**只读** token,存 mini `.env`,写端点一律不认它)。OneCreat 现在**只持自己的网关 token**(`account.Gateway`,`internal/account/boundary_test.go` 全树扫描守着它)。选 B 意味着多持一类高权限凭证 + 多一套平台写 API 错误处理,收益只是"少切一次 App"。 |

**对后续各期的约束**

| 期 | 约束 |
|---|---|
| **M1–M5** | OneCreat **不得持有任何教师平台凭证**(读或写)。`internal/account` 不新增凭证类型;若有人加,`boundary_test.go` 的扫描范围应同步扩到新的 env 名。 |
| **M4** | 工作台的"平台材料"子页只做**本地产物管理**(列 `02_平台材料/` 下的候选文件、标注 `platform.file_type`、给出勾选清单),末尾给一句人话提示:"上传请在 iOS OneUpTasks 完成"。**不做上传按钮,也不做假的上传态。** |
| **注册表** | `workflow_registry.json` 的 `platform{file_type, upload_via}` 字段**照原样保留**——它是给 iOS 端读的契约,OneCreat 只写不用。这一条要写进 v17 收口说明(见 `02_注册表v17收口说明.md`)。 |
| **线 C** | 与"老师级授权模型"一起重新评估。重评的前置条件是:平台侧先有按老师粒度的写授权(规划 §7.2 平台侧前置项),否则 B 只是把 Keychain 的边界换个地方破。 |

### 3.2 字段草案(向后兼容)

```jsonc
{
  "code": "P26C-020",
  "short_name": "飞鸟志",
  "full_name": "校园鸟类声纹多样性监测站",
  "student": "学生102",
  "line": "C",
  "assignee": { "type": "student", "id": "card_<已脱敏>", "name": "学生102" },
  "needs_outsourcing": false,

  "stage": 3,                                  // 已有字段,语义不变:1-8 整数
  "stage_updated_at": "2026-08-23T10:00:00+08:00",  // 新增:RFC3339 带时区
  "stage_source": "kanban-migration"           // 新增:枚举,见下
}
```

| 新字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `stage_updated_at` | string | RFC3339(带 `+08:00`) | 最后一次 stage 变更时间。**迁移写入时统一用迁移执行时刻**,不伪造历史时间 |
| `stage_source` | string | `kanban-migration` \| `onecreat` \| `sync-init` \| `manual` | 谁写的这一次 stage。`kanban-migration` = §3.3 的一次性迁移;`onecreat` = 决策收件箱拨段位;`sync-init` = 历史上 `project_sync`/`establish_project.py` 写的初值;`manual` = 人手改 |

**兼容性约束(硬)**

1. **不删、不改名任何现有字段;保留每份文件既有键序**(2026-08-23 实测:27 份存在 **4 种键序**,由三条写入路径各自 append 形成——见 `05_夹具与基线.md` §2/§4)。新字段一律 **append 到文件末尾**(与三个外部脚本的行为一致),**不做规范化重排**——用普通 Go struct 整写会改脏 16 份文件的键序,M1 必须用保序写回(json.Decoder token 流或有序 map),并以 27 份真实文件做 round-trip 黄金测试;Go 侧序列化必须 `SetEscapeHTML(false)` + `SetIndent("", "  ")`。
2. 缩进 2 空格、UTF-8、`ensure_ascii=False`、文件尾换行 —— 与现有文件同款(**例外:`P26C-028` 无尾换行,写回时原样保留**)。
3. 新字段**可缺失**:读取方遇到缺失时,`stage_updated_at` 视为未知、`stage_source` 视为 `sync-init`。外部脚本**不认识新字段也不会坏**——~~待核~~ **已核(05 §4,S1-6 通过)**:三条写回路径(`establish_project.py` 只新建、`assign_project.py:137`、`reline_project.py:107`)都是 `json.loads → dict 改 key → json.dump` 整份重写,未知字段原样保留;`project_sync.py`/`topic_index.py`/`refresh_board.py` 从不写回。**新字段直接进 `project.json`,不建 `.onecreat/` 侧车**(dot 路径被 `collect_project_files:588-590` 整树排除,永远同步不到 NAS)。
4. `stage` 的取值校验照抄 `_project_stage_int` 的口径:**必须是 1–8 的数学整数,`3.9` 判非法而不是截断**。

### 3.4 冲突规则:"只给新卡写初值、绝不覆盖"这条铁律怎么平移

这条铁律的**真实含义**是:「**stage 是人的判断,自动化只能补空,不能改人拨过的值**」。它保护的是"权威端的人工输入"。平移时**保住语义、换掉方向**:

| 阶段 | 铁律的形态 |
|---|---|
| **今天(NASApp)** | 权威端 = P 卡。自动化(`project_sync` → `upsert`)**只在 `card.stage is None` 时写一次**。 |
| **M1–M4(并行)** | 权威端仍是 P 卡。**`project.json` 侧的镜像不适用这条铁律**——它是副本,本来就该被覆盖。但反向保护要在:**OneCreat 不提供改 stage 的写入口**(§2.3),且镜像遇到 `stage_source=="onecreat"` 时**拒绝覆盖并报警**,把违规暴露出来而不是悄悄抹平。 |
| **M5 之后** | 权威端 = `project.json`。铁律原样翻面:**任何自动化(含 `project_sync` 回推 P 卡、含未来的批量脚本)只允许在 `project.json` 缺 `stage` 时写初值**(`stage_source="sync-init"`);**只有决策收件箱的「段位」决策**能覆盖已有值,并写 `stage_source="onecreat"` + 刷新 `stage_updated_at`。这条要做成 `internal/project` 的一个函数级不变量,配单测。 |

**实现建议(伪代码,Go 侧)**

```go
// internal/project —— stage 写入的唯一入口,铁律就长在这里。
// 规则:自动化只能补空;覆盖已有值必须是人的显式决策。
func (s *Service) SetStage(ctx context.Context, code string, stage int, src StageSource) error {
    if stage < 1 || stage > 8 {              // 照抄 _project_stage_int 的口径:3.9 判非法,不截断
        return ErrStageOutOfRange
    }
    p := s.load(code)
    if p.Stage != 0 && src != StageSourceOneCreat {
        // 自动化(sync-init / 镜像)撞上已有值 → 不写,交给对账报告
        return ErrWouldOverwriteHumanStage
    }
    p.Stage, p.StageUpdatedAt, p.StageSource = stage, now(), src
    return s.saveAtomic(p)                    // 临时文件 + rename,与 NASApp 同款原子写
}
```

```python
# scripts/migrate_stage_to_project_json.py —— 一次性,只读 NAS、只写 Mac 的 project.json
# 铁律:除 stage / stage_updated_at / stage_source 外,一个字段都不动;字段顺序与格式保持原样。

def main(dry_run: bool):
    projects = scan_projects(KETI_ROOT / "01_在研项目")   # 跳过下划线开头目录(_未立项 等)
    cards    = fetch_project_overview()                  # {code: stage}，读 /api/internal/project-overview
    registry = fetch_project_codes()                     # 只用于计数对账

    reconcile_counts(projects, cards, registry)          # 不一致就直接退出，不猜

    now = rfc3339_local()
    report = []
    for p in projects:
        data  = read_json_preserving_format(p.json_path) # 保留 key 顺序与缩进
        old   = data.get("stage")
        new   = cards.get(p.code)
        if new is None:
            report.append(Missing(p.code, old)); continue      # 卡上没有 → 保留文件里的值，记异常
        if not is_stage_int(new):                              # 照抄 _project_stage_int：3.9 判非法
            report.append(Invalid(p.code, new)); continue
        report.append(Change(p.code, old, new))
        if dry_run:
            continue
        data["stage"] = new
        insert_after(data, "stage", "stage_updated_at", now)    # 追加在 stage 之后
        insert_after(data, "stage_updated_at", "stage_source", "kanban-migration")
        atomic_write_json(p.json_path, data)                   # tmp + os.replace

    write_report(report)
```
