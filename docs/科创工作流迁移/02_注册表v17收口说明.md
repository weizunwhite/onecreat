新增的 `notes` 内容（都是从散落各处收进来的领域约束，不是我编的）：

- **单题发散** —— 产物 frontmatter 的 `source` 必须写「深度产题」，写「单题发散」会被题索引器降级成「存量」（`server.ts:1020-1022`）。
- **立项** —— 快速/深度两档的一句话对照（详见本文 §5）。
- **教案** —— 每节必须打单值「对应流程」标签，取值只能来自 `enums.teaching_flows`；标准 12 节完整覆盖十流程。
- **课件** —— v16 `status_note` 那句交付说明。
- **论文** —— 「论文图不自动嵌、要人工组装」这条刻意保留的人工把关点。
- **匿名化检查** —— 只检查不改源文件；金鹏不得出现姓名/校名/师名。

### 2.4 校验（v16 只有 3 条，v17 有 21 条）

v16 的 `validateRegistry()`（`workflow-registry.ts:67-83`）只查三件事：有 `version/stages/materials`；材料的 `type/skill/stage` 非空且 stage 存在；材料 type 不重复。

v17 的 `Validate()` 增加到：

1. `schema_version == 17`
2. 17 个必备枚举一个不能少
3. 每个枚举的 `values` 非空、无重复、无空串
4. 枚举的 `detail` 只能出现在 `values` 里，且给出 `detail` 时必须**全覆盖**
5. `naming.groups` 不许复活
6. `naming.groups_ref` 必须指向 `enums.groups`
7. `naming` 必填项齐全
8. 阶段 id 唯一、非空
9. 阶段 `order` 从 1 开始**连续**
10. 阶段 `kind` ∈ `enums.material_kinds`
11. `stages` 块与 `enums.stages` **互相全覆盖**
12. 材料 `type` 唯一、非空
13. 材料 `stage` ∈ 已注册阶段
14. 材料 `kind` / `status` / `default_engine` / `modes` / `default_mode` ∈ 对应枚举
15. `default_mode` 必须在自己的 `modes` 里
16. `outputs.frontmatter_kind` ∈ `enums.frontmatter_kinds`
17. `platform.upload_via` ∈ `enums.upload_via`；`platform.file_type` 按 `|` 拆开逐个 ∈ `enums.platform_file_types`
18. `decisions` ∈ `enums.decisions`
19. `deps` / `soft_deps` 指向存在的材料，且不指向自己
20. 依赖图**无环**（`deps ∪ soft_deps` 一起做拓扑排序）
21. 别名目标存在、别名不与正式类型同名；`skills_not_materials` 里的 skill 不许同时是某个材料的 skill

外加 JSON 解码时 `DisallowUnknownFields()`：JSON 里加了字段而 Go 结构没跟上，装配期直接红，而不是被静默丢掉。

## 4. 十流程 vs 十一列：怎么处理的

事实（调研 §1.1(C)）：

- **权威**是 skill 里的**十流程**——教师平台进度轴 `flow_no` 是单值，教案每节按十流程打标签，平台直接读。
- NASApp 的 C 类看板（学生项目板）默认列却是**十一列**，硬编码在 `web/main.py:15398-15399`，两处不同源，已经漂移。

v17 的处理：

| | 处理 |
|---|---|
| **十流程** | 收进 `enums.teaching_flows`，**唯一权威**。`教案` 材料的 `notes` 明写"标签取值只能来自 `enums.teaching_flows`" |
| **十一列** | 收进 `enums.legacy_board_columns`，标 `read_only: true`，并在 `note` 里写死三句话：①漂移项；②只用于读懂存量 C 板数据；③**不得据此生成教案标签、不得据此建新板** |
| **两者的差** | 在 `legacy_board_columns.detail` 里逐列标注对应关系。差异有 **4 处**：多出的「通识基础」（十流程里**没有对应**），以及 3 处措辞漂移——「发现问题 vs 问题分析」「原型制作 vs 原型构建」「报告答辩 vs 报告与答辩」 |

**留给 M4/M5 的一个决定**：存量 C 板卡片如果落在「通识基础」列上，迁移时映到十流程的哪一格。本次不猜（NASApp 侧 C 板实际数据未核对），只把它标成"无对应"。

另外，教学内容 **8 阶段**（启发→调研→本质→可视→制作→测试→迭代→成果，`lesson-plan-generator/SKILL.md:32-40`）**没有**登记为枚举——它是教案正文的组织方式，不是进度轴，也没有任何字段引用它。SKILL.md `:63-74` 有 8→10 的对照表，需要时去那里查。

## 8. M1 接手注意事项

M1（领域内核，规划 §8.2）会新建 `internal/project` / `internal/workflow` / `internal/topic` / `internal/numbering` 四个包。就注册表这一块，接手时请注意：

1. **只有一个入口**：`registry.Load()`。别在别处再 `os.ReadFile` 一份 JSON，也别把枚举抄进 Go 常量——抄一次就等于把 v16 的病带过来了。要遍历枚举用 `reg.EnumValues(name)`。
2. **未注册类型必须报错**。`ResolveSkill` 返回 `(string, bool)`，`false` 就是 fail-closed 信号，别 `if !ok { return defaultSkill }`。
3. **别名只在入口处归一**：`reg.Canonical(type)` 只用于接收外部输入；展示、落盘、事件里一律用正式类型。
4. **`Load()` 每次都重新解析并校验**，返回新的 `*Registry`。目前没有缓存也不需要（没有热路径）。若 M2 发现材料列表进了每轮 prompt 的热路径，再加 `sync.Once` 缓存，但要同时把返回值改成只读视图——现在的 `*Registry` 是可写的，别在共享后改它。
5. **加字段的流程**：改 JSON → 在 `registry.go` 加对应 Go 字段（`DisallowUnknownFields` 会强制你加）→ 如果是枚举语义，同时加进 `enums` 与 `TestEnumsDefinedOnce` 的 `scalarFields`/`listFields` 映射 → 跑 `go test ./internal/workflow/...`。
6. **加材料的流程**（对应规划铁律 4）：先改注册表，再补 skill，再让消费侧使用。新材料若引入新的 `platform.file_type`，记得同时进 `enums.platform_file_types` **并与 teacher 仓的枚举核对**（见 §9 不确定项）。
7. **拓扑序可以直接用**：`reg.MaterialOrder()` 返回满足 `deps ∪ soft_deps` 的生成顺序，M2 编排一键材料链时不用自己再实现一遍。注意软依赖也算边——如果 M2 认为软依赖不该约束顺序，那要改的是 `topoSort` 的语义并补测试，而不是绕开它。
8. **`enums.thread_statuses.planned`**：`awaiting_decision` / `decided` 现在只在 `planned` 里躺着。M3 决策收件箱落地时把它们移进 `values`，并同步 `event.Kind` 注册（规划 §4.6 / §8.0 D10）。
9. **`internal/workflow/registry` 不许 import 上层**。M1 建 `internal/workflow`（父包）时，让父包 import registry，别反过来。
