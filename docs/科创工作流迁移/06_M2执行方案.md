# 06 · M2 一键材料流水线 —— 执行方案(2026-08-23,编排者)

> 范围 = 路线图 M2:材料作业 = 会话;依赖注入 / 重试 / 假成功检测 / 组装说明;产物落桶;事件 Kind 注册;evidence 持久化(workflow.jsonl)。验收 = CLI 对沙箱项目生成「技术方案 → 教案」链,证据对账通过。
> 看图质检:本期只留 hook 点(vision 未接线时跳过并如实标注),完整实现后置。

## 1. 两个 M2 拍板(编排者定,依据 M0/05)

1. **headless 材料作业的门禁口径:没有 ask,只有 allow/deny。**
   材料作业会话使用**专用权限策略**:工作区内文件读写 allow、白名单命令(mkdir/ls/cat 等只读与生成类)allow,其余一律 deny——不做"ask 降级放行"(堵 05 §4/N4 那条口径缺口的 M2 半边;dsh 侧 handlePreExecute 的通用修复另列)。deny 即工具失败回模型,模型可绕道或作业失败,**绝不静默放行**。
2. **验收在沙箱,不在真实项目。**
   e2e 把飞鸟志复制到 scratchpad 沙箱跑;真实 DeepSeek 调用的 e2e 用 `ONECREAT_WORKFLOW_E2E=1` 门控(默认跳过)。M1–M4 期间 CLI `gen` 对真实课题目录默认拒绝,`--allow-real` 显式放开(写入七目录虽是双写禁区允许项,但生成质量未定型前不污染真实项目)。

## 2. 分层与接口契约(两条并行线的合同)

```
internal/workflow(纯领域,不 import boot/control/engine/agent)
  job.go       材料作业状态机:Resolve(依赖检查/拓扑) → Assemble(组 prompt) → run(经 Runner) →
               Verify(假成功检测) → 重试 1 次 → Collect(产物归位校验 bucket.Classify) → 记账
  runner.go    type RunRequest { ProjectDir, MaterialType, Prompt string; Timeout time.Duration }
               type RunResult  { FinalText string; WrittenFiles []string }
               type Runner interface { Run(ctx, RunRequest) (RunResult, error) }   // 唯一执行接缝
  assemble.go  prompt 装配:skill 正文(经 internal/skill 索引按名解析)+ 依赖材料产物全文(来自 status 的 Paths)
               + 七目录环境说明(新写,替代 NASApp 的"本环境说明"补丁——大部分补丁按 M0 结论删除)
               + 落桶指令(材料 → 目标桶) + 「不要问任何问题,缺信息合理假设」
  journal.go   .onecreat/workflow.jsonl append-only:material_started/succeeded/failed/skipped
               {ts, material, session_hint, outputs[], receipts_summary, retries, reason?}
               + 读取端 Replay() 供 status/UI 用
  quality.go   假成功检测(WrittenFiles 里无落入目标桶的交付物 → 失败)· 组装说明(docx+drawio 无 png →
               生成《图表组装说明.txt》)· 看图质检 hook(vision 未配置 → 记 skipped)
internal/cli(装配层)
  workflow_run.go  ControllerRunner:boot.Build(Workspace=项目目录, 材料作业权限策略, engine 可选)
                   → Submit(prompt) → 等 turn 结束 → 从 evidence receipts/checkpoint 收 WrittenFiles
  workflow.go      新增子命令 gen:reasonix workflow gen <项目> <材料> [--engine ...][--mode 快速|深度]
                   [--dry-run 只打印 prompt][--allow-real]
internal/event + eventwire
  新增 Kind:workflow_material(durable)——进度/结果帧,M4 UI 消费;本期 CLI 不渲染只发。
```

依赖注入口径:硬依赖(deps)缺失 → 作业拒绝并提示先生成上游;软依赖(soft_deps)存在才注入。产物检测沿用 `workflow.ProjectStatus` 的判定(已知"宁漏勿误",漏判导致的重复生成可接受)。

## 3. 分工

- **W1(领域)**:job/runner/assemble/journal/quality + FakeRunner 单测(临时项目目录,断言依赖拒绝/重试/假成功/落桶校验/journal 追加与回放)。
- **W2(装配)**:ControllerRunner + CLI gen + 材料作业权限策略 + 事件 Kind 注册(eventwire 三处守卫);沙箱 e2e(FakeProvider 或 httptest 网关,不花真钱)+ 门控的真模型 e2e。
- 编排者:验收 = 沙箱里 `gen 技术方案` → `gen 教案`(教案依赖技术方案)全链,journal 可回放,守卫全绿。
