# onecreat 平台重构蓝图（硬件优先 → 垂直教培 agent 平台）

> 定位：本地版 Claude Code + CoWork 的结合体，垂直教培。从选题到参赛材料端到端。
> 结论：**不重写引擎，翻面前台 + 做减法。** 下面每一步都保持硬件可用、灰度推进。

## 一、证据结论（架构盘点 wf_23c5c2ac-04c）

| 层 | 硬件耦合度 | 处置 |
|---|---|---|
| **引擎** `internal/`（agent/control/tool/skill/plugin/memory/provider/permission/command/hook/event/boot/checkpoint/diff/sandbox/jobs，共 16 包） | **0（零耦合）** | **不动**，直接复用到任何教培任务 |
| **前端 IA** `App.tsx` | 高（顶部双 tab、侧栏硬件按钮、mainView 状态机） | 翻面 |
| **HardwarePanel.tsx** | 60% 通用 / 40% 硬件专属 | 抽通用 `WorkflowSurface` |
| **skills 系统** | 0 | 已就绪，缺首页入口 + 分类元数据 + 编排 |
| 其它面板（Memory/History/Settings/Capabilities/Knowledge/Workspace/Composer/Transcript/Welcome） | 0 | 复用 |

引擎是个**通用 agent 平台**，硬件只是贴在上面的一个垂直层。让人觉得"太硬件中心 / 工作流有问题"的，是前台呈现 + 几处被过度过程化的定制流程（auto-plan、硬编硬件 prompt、强制门）。

## 二、目标架构

```
                ┌─────────────── 首页 = 任务/技能启动台 ───────────────┐
                │  [硬件项目] [竞赛论文] [课程教案] [研究日志] [金鹏包] … │  ← 每张卡 = 一个 skill
                └───────────────────────────┬──────────────────────────┘
                                            │ 点一张卡 = 在对话里启动该 skill
                                            ▼
   ┌──────────── 对话(唯一主视图) ────────────┐   ┌─ 按需右侧抽屉/面板 ─┐
   │  通用 agent loop · 工具 · MCP · skills    │ ◄─┤ 硬件工作台(编译/烧录) │  ← 仅"真需要硬件按钮"的垂直才有定制 UI
   │  知识库 · 记忆 · 多标签 · 会话             │   │ 知识库 · 记忆 · 历史   │
   └──────────────────────────────────────────┘   └──────────────────────┘
```

**三条设计铁律**：
1. **技能优先，不是硬件优先**：首页是垂直启动台，硬件只是其中一张卡。
2. **绝不"一个垂直一个定制面板"**（最贵、不可扩展的坑）。默认：垂直 = skill + 轻量启动卡，活儿在对话里干。**只有像硬件"编译/烧录"这种真要硬件按钮的，才做定制表面**，且复用通用 `WorkflowSurface`。
3. **模型自己判断，做减法**：剥掉 auto-plan、强制门、重型硬编 prompt（CC 路线）。硬件防幻觉能力（catalog/board facts）保留为 skill/MCP，不再是写死的前台流程。

## 三、分阶段（文件级，每阶段独立可上线、硬件始终可用）

### Phase 0 ✅ 架构盘点（已完成 = 本蓝图）
验证"引擎零耦合、不用重写"。

### Phase 1 — 前台翻面：首页改技能启动台（高收益、低风险）
- `Welcome.tsx`：从"示例提示"改成**垂直启动台**（卡片网格，先硬编 5~6 个垂直：硬件项目/竞赛论文/课程教案/研究日志/金鹏包/通用对话）。点卡 = 注入对应 skill 的启动 prompt 进对话。
- `App.tsx:1368-1391`：删除顶部"对话 | 硬件编程"双 tab。
- `App.tsx:1144-1151`：侧栏"硬件编程"从一级入口降级——硬件改成**按需打开的右侧抽屉/工作台**（由硬件项目卡或会话内按钮触发），不再占 `mainView`。
- `App.tsx:374 / 627-641 / 1452-1469`：`mainView` 状态机从 `chat|hardware` 简化为"chat 主视图 + 可选右侧面板"。
- 侧栏会话列表标注类型（chat/hardware/research），为"最近任务"做准备。
- **验证**：硬件项目卡 → 仍能进硬件工作台编译/烧录；普通问答不再有硬件噪音。
- **风险**：低（纯前端 IA，引擎不动，硬件逻辑整体保留只是换入口）。

### Phase 2 — 抽通用 `WorkflowSurface`（中等）
- 从 `HardwarePanel.tsx` 抽出 60% 通用骨架 → 新建 `components/WorkflowSurface.tsx`：
  - 复用：工具栏骨架(638-742)、任务输入+按钮(905-936)、操作列(938-957)、结果卡(812-872)、证据卡(875-902)、详情折叠(960-1033)、状态格式化(256-291)。
  - 参数化：`actions`、`selectors`、`bridge` 由各垂直注入。
- `HardwarePanel` 重写为 `WorkflowSurface` 的**第一个实例**，把硬件专属部分（boardPresets 42-51、硬件 actions 53-72、平台检测 80-91、runOneTouch MCP 395-452、buildGuidePrompt/DirectPrompt 105-254、证据导出 483-505 等）作为注入项。
- 再加 1~2 个**纯 skill 卡**垂直（竞赛论文/教案）——它们**不需要定制表面**，点卡直接在对话里跑 skill，验证"技能优先"路子。
- **验证**：硬件功能与 Phase 1 等价；新垂直能从卡片一键进对话跑 skill。

### Phase 3 — skill 元数据 + 启动台数据化（中等）
- `internal/skill/skill.go`：skill frontmatter 增加 `category` / `vertical` / `icon` 元数据字段（分类：硬件/竞赛/教学/通用…）。
- `desktop/app.go` + `bridge.ts` + `types.ts`：暴露 skill 元数据给前端。
- `Welcome.tsx` 启动台从"硬编卡片"改成**按 skill 元数据自动生成**——以后加 skill = 自动多一张卡，零前端改动。
- **验证**：新增一个带 category 的 skill，首页自动出现对应卡。

### Phase 4 — CoWork 式编排（可选、增量、最后做）
- 引擎已具备多 skill 顺序执行（task 工具 spawn subagent）。新增"工作流配方"概念：把"金鹏参赛包 = 论文→PPT→匿名化→照片清单"定义成一个可一键触发、自动串起多个 skill 的 recipe。
- 落点：可先用一个**编排 skill**（纯 prompt 驱动，调用其它 skill）试水，不动引擎；不够再考虑引擎加轻量 orchestration。
- **验证**：一键"生成金鹏参赛包" → 自动产出多份材料。

## 四、复用 / 改动 / 新增 总账

- **复用（不动）**：整个 `internal/` 引擎、MCP、skills、知识库、会话、多标签、记忆、除 App/HardwarePanel 外的所有面板。
- **改动（聚焦）**：`App.tsx`（IA 翻面）、`HardwarePanel.tsx`→`WorkflowSurface`、`Welcome.tsx`（启动台）、`internal/skill`（元数据）、`styles.css`。
- **新增（增量）**：垂直启动卡、WorkflowSurface 组件、（可选）编排 recipe。
- **删/减**：auto-plan 强切（已做）、顶部双 tab、过度过程化的硬件强制门。

## 五、粗工作量与顺序建议

| 阶段 | 量级 | 上线价值 |
|---|---|---|
| P1 首页翻面 | 2~3 天 | 立刻不再"硬件中心"，体感最大 |
| P2 抽 WorkflowSurface + 2 个 skill 卡 | 3~4 天 | 验证可扩展性 |
| P3 skill 元数据驱动启动台 | 2 天 | 加垂直零前端成本 |
| P4 CoWork 编排 | 看深度 | 端到端杀手锏，可缓 |

**建议顺序：P1 先上**（收益最大、风险最低、立即解决"太硬件中心"），跑顺了再 P2/P3，P4 看精力。
