```bash

```

## 改完自查(别让人肉当编译器)

```bash
# 内核
CGO_ENABLED=0 go build ./...
# desktop Go
cd desktop && go build ./... && go vet ./...
# 前端
cd desktop/frontend && pnpm tsc --noEmit && pnpm build
```

到可提交的稳定点就 commit 作 checkpoint(不用 push,方便回退)。

## 红线 / 血的教训

- ❌ **不要把 reasonix 上游的流式渲染优化往这搬**。2026-06 实测:合帧 / `useDeferredValue`
  那批移植进来后流式**更差 + 多 bug**,已全撤回。根因:onecreat 的 `useController.ts` 已用
  `live?: LiveStream` 字段把流式 token 放在 `items` 之外(O(1) 更新、不重建 backlog),从根上
  解决了"每 token 重渲染",上游优化叠上去只会打架。真要提速先定位具体瓶颈 + **打包实测对比**。
- **desktop bridge 手工镜像**:改 `desktop/app.go` 的导出方法签名,必须同步 `desktop/frontend/src/lib/bridge.ts`(`AppBindings` 接口 + `makeMockApp` mock + 调用点)。Wails 按位置传参。
- **DeepSeek prefix cache 塑造 prompt 设计**:prompt append-only 增长(高缓存命中),压缩是刻意的缓存重置点;每轮运行态在 `Compose` 时注入,**永远不要进缓存的 system 前缀**。
- 改 `_components` 类组件前先 `grep` 确认谁真的 import 它(可能有同名死文件)。
