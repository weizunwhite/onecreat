```bash
cd /Users/localwork/06_System/onecreat
# 版本号每次递增
bash scripts/web-build.sh darwin/arm64 v1.2.x     # 单平台点测 -> dist/onecreat-web-darwin-arm64.tar.gz
make release-web VERSION=v1.2.x                   # 全平台 + SHA256SUMS(CI 的 release-web.yml 就是跑这个)

# 本机装机验证:解压即用(主程序 + onecreat-hardware-mcp + README 同目录)

```

**发布三步**(主分发形态):

1. **打 tag**:`git tag web-vX.Y.Z && git push origin web-vX.Y.Z` → GitHub Actions `release-web.yml`
   跑 `make release-web`,出 5 个平台包 + `SHA256SUMS` + `latest.json`,作为 GitHub Release(镜像)。
2. **上传阿里云**(主渠道,`UPDATE_CHANNEL`):把 `dist/` 里的 5 个发行包和 `latest.json` 传到阿里云
   nginx 的 `/var/www/onecreat/`(对外 `http://47.95.176.214/onecreat/`)。客户端启动就是 GET 这个
   `latest.json` 比对版本。`latest.json` 里的下载直链基址默认就是这个地址(打包时 `RELEASE_BASE_URL` 可改)。
3. **验证更新提示**:装一台旧版,启动后页面顶部应出现更新横幅、点「去下载」能打开下载页。

> `latest.json` 的格式与更新流程细节见 [`docs/Web模式.md`](Web模式.md) 的「更新检查」节。
> 阿里云机器、免密公钥、nginx 根目录见记忆库 `onecreat-ota-firmware-server-aliyun` / `ota-remote-flash` skill。

## 本地 API / 平台账号模式

当前开发默认 **local-first**:不依赖 teacher 平台、不要求登录、不自动走 `/api/onecreat/v1` 网关。先在
onecreat 本地配置 API key / provider,把软件主体开发好。

只有以后要回归测试 teacher 账号、订阅档位和点数网关时,才显式启用平台模式:

```bash
ONECREAT_ACCOUNT_MODE=platform \
ONECREAT_PLATFORM_URL=http://127.0.0.1:3000 \
exec "/Applications/onecreat.app/Contents/MacOS/reasonix-desktop"
```

- 平台模式实测前先在 teacher 仓库起本地 dev server(`localhost:3000`)。
- 正式分发版默认是本地 API 模式;不要因为本机残留 teacher session 就自动改走网关。
- teacher 平台侧(网关/超管后台/迁移)的改动,**由用户自己合并部署**,不在本仓库。

## 改完自查(别让人肉当编译器)

```bash
# 内核
CGO_ENABLED=0 go build ./...
# desktop Go(默认 = Wails 桌面版)
cd desktop && go build ./... && go vet ./... && go test ./...
# desktop Go(Web 模式的构建标签也要过)
cd desktop && go build -tags web ./... && go vet -tags web ./... && go test -tags web ./...
# 前端
cd desktop/frontend && pnpm tsc --noEmit && pnpm build
```

到可提交的稳定点就 commit 作 checkpoint(不用 push,方便回退)。

## 红线 / 血的教训

- ❌ **不要把 reasonix 上游的流式渲染优化往这搬**。2026-06 实测:合帧 / `useDeferredValue`
  那批移植进来后流式**更差 + 多 bug**,已全撤回。根因:onecreat 的 `useController.ts` 已用
  `live?: LiveStream` 字段把流式 token 放在 `items` 之外(O(1) 更新、不重建 backlog),从根上
  解决了"每 token 重渲染",上游优化叠上去只会打架。真要提速先定位具体瓶颈 + **打包实测对比**。
- **desktop bridge 手工镜像**:改 `desktop/app.go` 的导出方法签名,必须同步 `desktop/frontend/src/lib/bridge.ts`(`AppBindings` 接口 + `makeMockApp` mock + 调用点)。Wails 按位置传参。
- **DeepSeek prefix cache 塑造 prompt 设计**:prompt append-only 增长(高缓存命中),压缩是刻意的缓存重置点;每轮运行态在 `Compose` 时注入,**永远不要进缓存的 system 前缀**。
- 改 `_components` 类组件前先 `grep` 确认谁真的 import 它(可能有同名死文件)。
