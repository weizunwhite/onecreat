## 3. 现状:门禁在 `feat/dsh-engine` 上是怎么成立的

### 3.1 机制(一张图)

```
模型要调 write/edit/bash/…
   │
   ▼  dsh-tools 调度器(node_modules/@deepseek-ai/dsh-tools/lib/index.js:3105)
   │  const gate = await ctx.waterfall(…, "tools/pre-execute", exec, () => ({kind:"allow"}))
   │  ──► 派发之前先跑 waterfall;结果 deny → 把 `Error: <reason>` 当工具结果回给模型,工具**不执行**
   │
   ▼  onecreat-control 插件(dsh/plugins/control/index.js:252-268)—— 整个闭包里**唯一**的 pre-execute 监听者
   │  toolCtx.on('tools/pre-execute', async (exec) => await ask('onecreat/tool.preExecute', {...}, 0, exec.signal))
   │  不设超时(等真人);exec.signal 取消 / 通道断开 → 返回 deny(fail-closed)
   │
   ▼  通知 onecreat/tool.preExecute {id, sessionId, name, arguments}   ── stdio ──►  Go
   │
   ▼  Go 侧 Engine.handlePreExecute(internal/engine/dsh/sidecar.go:782-812),一次做三件事:
   │    1. Decide = boot.dshDecider(internal/boot/dshengine.go:126-148)
   │         计划模式开 & 非只读工具 → deny(硬门,不靠 dsh-plan-mode 的软提示)
   │         permission.Policy.Decide → deny / ask / allow(deny 名单、ask 规则与 native 同一份)
   │    2. ask → Controller.RequestApproval(复用 native 审批 UI / 会话内授权记忆 / YOLO 语义);
   │              headless 无 Approver → 放行(与 native permission.Gate 一致)
   │    3. allow → PreEdit = Controller.enginePreEdit(internal/control/engine.go:76)
   │              对参数里的 file_path 等做 checkpoint 快照(Create/Modify),供文件级 rewind
   │
   ▼  通知 onecreat/tool.preExecute.done {id, decision, reason}   ◄── stdio ──  Go
   │
   ▼  allow → 正常 dispatch;deny → 模型收到 Error,文件/命令不发生
```

两个相邻事实(确认过闭包源码):`dsh-plan-mode` 不挂 pre-execute(README 自述只是软引导);`dsh-user-approval`
只在有人返回 `ask` 时才被 `serviceAsk` 调到——我们的钩子只回 allow/deny,所以 `approval/request` 桥
(`handleApproval`)在当前 profile 下是**备用路径**,主路径是 pre-execute 的 `ask → Go Approver`。

### 3.3 对评审三个前提的修正

1. **"必须 server→client 请求 + client 能 respond"** —— dsh 的 `JsonRpcLineTransport` 两端都有 `request()`
   (`dsh-sdk-protocol/lib/types/transport.d.ts:85`),sidecar 本来就能向 Go 发请求;我们**故意**用"带 id 的通知对",
   让 Go `LineClient` 只认两种入站帧(`protocol.go:48-50` 注释)。语义等价:sidecar 在 `await` 期间工具不执行。
   linerpc.go 的"第三种 case"与 `respond` 不是门禁的前提。
2. **"卡在 dsh 那侧的架构改动"** —— 不存在。`tools/pre-execute` 是 dsh-tools 的一等扩展点,官方 SDK server
   只是没把它接到 JSON-RPC wire 上;接 wire 是我们插件的事,已做。
3. **"计费被绕过"** —— 见 §1 最后两行。
