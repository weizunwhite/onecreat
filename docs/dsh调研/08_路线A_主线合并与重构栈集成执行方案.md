## 2. 集成策略:一次 merge,不 rebase 94 个提交

- 新建 `integrate/refactor-stack-on-dsh`,**从栈顶切**,`git merge origin/main-v2`(此时 main-v2 已含 #39)。冲突只解一次;

  而且栈式 PR 的 base 链全要重指,没有收益。

### 3.3 工具门禁:feat 的 `dshDecider + handlePreExecute + PreEdit` 改为调用栈的 `toolpolicy.Pipeline.Before/After`

- 栈:`Pipeline` 由 `agent.Agent` 持有(`executor.Policy()`),`Before(ctx, Call{ID,Name,Args,ReadOnly,Preview})` 按固定顺序
  plan mode → gate → PreToolUse hook → checkpoint 快照(PreEdit(diff.Change))→ ctx 注入;`After(ctx, Call, result, err)` 记证据 + PostToolUse。
  `turnState.SetPlanMode` 已把计划模式写进 Pipeline;`EnableInteractiveApproval` 把 `approvalBroker.Gate()` 装进 executor。
- feat:`Options.Decide/Approver/PreEdit/Ledger/Tools` 五个注入点,Go 侧 `handlePreExecute` 三合一;`Consume` 直接往 `*evidence.Ledger` 记。
- 集成后(dsh 包只认**函数类型**,不 import 策略包):
  - `dsh.Options` 收敛为:`PreExecute func(ctx context.Context, call ToolCallInfo, readOnly bool) (allow bool, blockOutput string)`、
    `PostExecute func(call ToolCallInfo, res ToolResultInfo)`、`ToolInvoke func(ctx context.Context, name string, args json.RawMessage) (string, error)`
    (工具桥 `complete_step`)、`OnTodoWrite func(raw json.RawMessage)`(喂账本的 todo 事件)。删除 `Decide/Approver/PreEdit/Ledger/Tools`
    及 `Decider/Approver/ToolLookup` 类型,`handlePreExecute` 变成一行调 `PreExecute`,deny 时把 `blockOutput` 作为 reason 回 wire。
  - `boot`(不在 dsh 包)把它们接到 `executor.Policy()`:`PreExecute` = `pipeline.Before(ctx, Call{ID,Name,Args,ReadOnly: dshToolReadOnly(name) 或注册表,
    Preview: dshPreview(name,args)})`;`dshPreview` 沿用 feat `editPathsFromArgs`+读当前文件 → `diff.Change{Create|Modify}`
    (feat `control/engine.go` 的 `enginePreEdit` 逻辑搬到这里,`normalizeEditPath` 的 `/tmp→/private/tmp` 处理保留);
    `PostExecute` = `pipeline.After(ctx, call, res.Output, errIf(res.IsError))`;`ToolInvoke` = `registry.Get` + `Before/Execute/After`;
    `OnTodoWrite` = 现在 `Consume` 里喂 todo 的那段(`Ledger.RecordTodos` 或等价,以 feat 源码为准)。
  - 于是 **PreToolUse hook 能阻断 dsh 调用**(这是复核 AR-R01 验收第 5 条,feat 之前没覆盖)、计划模式/审批/checkpoint/证据全部走同一份 Pipeline。
    `boot.dshDecider`/`dshengine_test.go` 的计划模式硬门与注册表优先逻辑**不再需要**(Pipeline 已做),但 `dshToolReadOnly` 名单保留
    (Pipeline 需要 `ReadOnly`),其单测保留。
  - `onecreat/planMode.set`(dsh 自己的软引导)保留为**可选接口** `PlanModeAware{SetPlanMode(bool) error}`,由 `turnState.SetPlanMode`
    在引擎实现了它时顺带调用;不实现也不影响硬门。
- 验收:真 sidecar e2e 全部迁移并通过(`e2e_gate_test.go` 改为注入 `PreExecute`/`PostExecute` 版本,或直接用 boot 装配的完整路径);

### 9.6 顺手发现但没动的

1. **`internal/account/boundary_test.go` 的守卫可以被一个 const 绕过。** 它匹配的是字面量 `os.Getenv("ONECREAT_TIER")`;feat 的 `sidecar.go` 写的是 `const gatewayTierEnv = "ONECREAT_TIER"` 加 `os.Getenv(gatewayTierEnv)`,于是整份扫描看不见它。**这次修了违规的代码(改注入),没有动守卫本身** —— 收紧它(比如扫字符串字面量)会误伤 `config.go` 里作为默认配置值的同名字符串,需要单独一条改动来做。
2. **`desktop.engineLabel` 只看 `ONECREAT_ENGINE`,不看 `cfg.Engine`。** controller 建好之前显示的引擎名可能与实际装配的不一致(feat 既有行为,本次只补回了被合并删掉的 `os` import)。
3. **`e2e_gate_test.go` 测的是引擎自带的 `Decide→Ask→Approver` 分支,而生产路径已经走 `Pipeline.Before`。** 两者语义等价(Gate 内部就是 ask→approver),但测的不是跑的那条线。建议本机把这 5 条改成注入一条真 `toolpolicy.Pipeline` 后复跑。
