# 3. Wave A — dsh 安全、能力与生命周期

必须关闭：AR-R01、AR-R02、AR-R04、AR-R05、AR-R06。

## A1. dsh tool policy：必须 fail-closed

先检查 dsh 当前协议是否支持 hosted/delegated tool execution。

- 若支持：dsh 只能提出 tool call，由 OneCreat 执行：
  `toolpolicy.Before → Tool.Execute → toolpolicy.After → result 回传 dsh`。
- 若不支持：禁止 dsh 使用 writer/shell/tool execution；装配时明确拒绝不安全配置，或只允许纯模型/只读能力。

不得在工具已经执行后，根据 `tool/call` 显示事件做事后审批。

必须测试 Permission deny/ask、plan mode、PreToolUse veto、checkpoint-before-edit、Evidence receipt、Memory/Jobs context。

## A2. Capability enforcement

- Controller 暴露只读 `Capabilities/Supports`；
- 所有依赖能力的操作在修改任何状态前校验；
- dsh 当前不支持的 New/Resume/Fork/Branch/Switch/Rewind/Summarize/Approval 等必须 typed error；
- HTTP 返回明确 409/422；Desktop/CLI 禁用并显示原因；
- 后端校验不能依赖 UI。

不得把这些操作添加到 `TurnEngine`。

## A3. Cancel / crash recovery

- 建立 sidecar lifecycle state；
- cancel 杀进程后必须安全 re-Boot，或把 session 标成 terminal 并阻止下一轮；
- crash 与 cancel 走同一恢复模型；
- 下一轮不得复用旧 `LineClient`。

必须有真实 fake-sidecar 集成测试：turn → cancel/crash → next turn。

## A4. 分离 native/dsh assembly

重构 `boot.Build`：

- Application/runtime 公共部分；
- Native 专属 Provider/Tool/MCP/Agent；
- dsh 专属依赖；

dsh 模式不得因 unused native provider/key 缺失失败，也不得无意义启动 native MCP/tools/jobs。

## A5. Credential / child env

- dsh 子进程环境采用 allowlist；
- 不得继承所有 `os.Environ()` secret；
- Gateway token refresh 必须能到达运行中的 dsh，或触发受控滚动重启；
- 测试 token generation 与其他 provider key 不泄漏。

# 4. Wave B — Session 与 Event 一致性

必须关闭：AR-R03、AR-R07、AR-R08、AR-R09。

## B1. Engine-specific Session backend

- Registry 记录真实 engine、stable session ID、opaque store ref；
- Native transcript 只由 native backend 解析；
- dsh transcript 只由 dsh backend 解析；
- 不得双写或用空 native JSONL 冒充 dsh；
- dsh 无 store 能力时，history/resume/fork 明确 unsupported，UI 标记 ephemeral。

Controller 的 History、autosave、Stop hook、plan proposal、title/preview 必须通过 backend，或在 unsupported 时明确禁用。

## B2. Reliable stream recovery

建立权威 snapshot，至少包含：

- transcript/history；
- running state；
- pending approvals/asks；
- session/tab/stream incarnation；
- latest durable sequence。

Frontend 在 `stream_reset`、reconnect、sequence gap 时 resync。强制 overflow E2E 必须证明最终状态一致且无重复。

## B3. Event identity / mapping

- Desktop envelope 填真实 session ID；
- session switch/rebuild 使用 stream incarnation；
- dsh ToolResult 携带 call ID/name/correlation；
- 每个 dsh durable event 明确映射、持久化、降级或 unsupported；不得默认静默丢弃 todo/step/compaction 状态。

## B4. Registry transaction

- 进程内共享一个 Registry；
- 跨进程使用 file lock、journal 或版本 CAS；
- 测试两个 Registry owner 的可控交错与 multi-process 更新。

# 5. Wave C — Workspace / Runtime 生命周期

必须关闭：AR-R10、AR-R11、AR-R12。

## C1. Workspace-local env overlay

- `.env` 不再调用 `os.Setenv`；
- 解析为 Workspace-local overlay；
- process env 是显式最高优先级 override；
- Provider、Plugin、subprocess expansion 使用显式 overlay；
- 两个 workspace 同名变量必须隔离。

## C2. Authoritative Workspace entry

- 合并 runtime scope 与 services 双注册表；
- scope/services/refcount/generation 在同一锁与 entry 下；
- last release 与 reopen 不得复用 closed service；
- WorkspaceSpec/config 变更需 generation/fingerprint 与 reconfigure/replace 语义。

必须有并发 barrier + race test。

## C3. Wire real TurnRuntime

- Boot 把 runtime Session 交给 Controller；
- 每轮 `BeginTurn`，使用 `Turn.Context`；
- 正常 End、取消 Cancel；
- per-turn temporary resources 注册在 Turn；
- 删除真实 turn 路径的 `context.Background()` 根。
