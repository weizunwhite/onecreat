## 一、我们调整 harness 的目的

**一句话:让一个便宜的弱模型,在教培垂直工作流上,稳定产出可信的结果。**

| 层 | 目的 | 判断标准 |
|---|---|---|
| **成本结构** | flash(¥1/M)经 harness 加持达到 pro 级表现,模型是可替换零件,harness 才是产品本体;分发给 B 端老师时 token 成本可控 | 同任务下,换更便宜的模型,成功率不塌 |
| **可信性** | 真机证据链是产品差异化:"灵活性归模型,保证归系统"——模型想吹牛,harness 不让 | 模型声称的每件事都有机器收据;伪造必拒 |
| **老师体验** | 用户是老师不是工程师,满屏红字+干等=产品不行;空转的每一轮都是真实等待和真实的钱 | 一次成功率、空转率(见验收指标) |

## 二、四条设计原则(新坑对号入座)

1. **错误消息是给模型的指令**
   每个失败必须用中文告诉模型"唯一正确的下一步",必要时带"不要做 X"的明确劝阻。
   实证:串口无输出的劝阻文案让 flash 不再 bash 瞎试;complete_step 中文指引(#65)模型看懂照做。

2. **事实硬注入,不让模型回忆**
   板卡默认密码、FQBN、引脚约束这类事实,flash 猜不到也不该猜——长在 board profile / catalog 里。
   实证:行空板默认密码 dfrobot 缺失 → 模型撞 Permission denied 十几次。

3. **已知流程铺平成工具,模型只做编排**
   串口采集、SSH 部署这类固定机制应长在 MCP 工具里(带正确参数),不让模型即兴写 bash。
   实证:模型靠运气发现 sshpass 救场——运气不是工程。

4. **收据宽容匹配,但不能伪造**
   证据校验太死=反复撞墙(路径形式、命令引号差异都 miss),太松=能吹牛。
   收敛方向:语义等价就认(后缀路径、归一化命令、工具核心名),凭空声称必拒。

## 四、验收指标(只看两个)

- **一次成功率**:任务从下达到完成,不需要人插手纠错。目标:五平台全部 ✅。
- **空转率**:报错的工具调用 / 总调用。实测轨迹:贪吃蛇 53% → 行空板 37% → **目标 <10%**。

诚实性不设指标——它是硬约束:证据账本必须保证"声称即发生过",任何修复不得削弱这一点。
